# Model Card — NormDef-FR Baselines

Version: 1.0.0  
Dataset: NormDef-FR 1.0.0  
Language: French (`fr`)  
Domain: French legal codes  
Task family: normative definition extraction and validation  

## 1. Overview

This model card documents the baseline systems released with NormDef-FR 1.0.0.

The baselines are designed to evaluate three complementary tasks:

1. term-definition extraction;
2. article-level definition detection;
3. candidate validation.

The released baselines are not intended to provide legal advice or to replace expert legal interpretation. They are research models for reproducible evaluation in legal NLP.

## 2. Tasks

### 2.1 Term-definition extraction

Input:

```text
A legal text segment containing a potential normative definition.
````

Output:

```text
term
definition
```

This task evaluates whether a system can extract the defined term and its corresponding definition from a legal text segment.

### 2.2 Article-level definition detection

Input:

```text
A full legal article.
```

Output:

```text
definition_article
true_negative
```

This task evaluates whether a system can distinguish an article containing a normative definition from a manually verified true negative article.

### 2.3 Candidate validation

Input:

```text
A candidate term-definition pair generated by the extraction pipeline.
```

Output:

```text
accepted
invalid
```

The `accepted` class groups candidates originally annotated as:

```text
valid_definition
partial
```

The `invalid` class corresponds to candidates annotated as:

```text
invalid
```

This task evaluates whether a model can filter usable candidates from noisy or incorrect extractions.

## 3. Released baselines

NormDef-FR 1.0.0 includes the following baseline systems.

| Baseline                          | Task(s)                                 | Description                                                                |
| --------------------------------- | --------------------------------------- | -------------------------------------------------------------------------- |
| Rule-based extraction             | Term-definition extraction              | Pattern-based extraction using French legal definitional markers           |
| TF-IDF word + Logistic Regression | Article detection, candidate validation | Word-level TF-IDF features with logistic regression                        |
| TF-IDF word + Linear SVM          | Article detection, candidate validation | Word-level TF-IDF features with linear support vector classification       |
| TF-IDF char + Linear SVM          | Article detection, candidate validation | Character n-gram TF-IDF features with linear support vector classification |
| CamemBERT                         | Article detection, candidate validation | Fine-tuned French Transformer model                                        |

## 4. Training data

The baselines are trained and evaluated on datasets derived from NormDef-FR 1.0.0.

The rule-based extraction baseline does not require supervised training, but it is evaluated on the test split.

The article-level benchmark uses manually verified true negatives.

A 5-fold cross-validation setting is also provided for TF-IDF candidate validation baselines.

## 5. Data splitting

All train/dev/test splits are grouped by article key.

This means that examples from the same legal article do not appear in more than one split for a given task. This constraint is important because a single legal article may contain several definitions or several candidate extractions with similar lexical and structural patterns.

The goal is to evaluate generalization to unseen articles rather than memorization of article-specific formulations.

## 6. Model details

### 6.1 Rule-based extraction baseline

The rule-based extractor uses explicit French definitional patterns, including:

```text
terme_colon_definition
on entend par
s'entend de
défini comme
est considéré comme
```

The extractor predicts:

```text
term
definition
```

It is intended as a transparent and interpretable baseline for highly formulaic normative definitions.

### 6.2 TF-IDF baselines

The TF-IDF baselines use classical sparse text representations combined with linear classifiers.

Two feature families are used:

```text
word-level TF-IDF
character n-gram TF-IDF
```

The classifiers are:

```text
Logistic Regression
Linear SVM
```

These baselines are included because legal definitional language often contains strong lexical and surface-form cues.

### 6.3 CamemBERT baseline

CamemBERT is used as a French pre-trained Transformer baseline for sequence classification.

It is evaluated on:

```text
article-level definition detection
candidate validation
```

CamemBERT is not evaluated for BIO sequence labeling in this release because NormDef-FR 1.0.0 annotates validated term-definition pairs, but does not yet provide exhaustive token-level BIO span annotations.

## 7. Evaluation metrics

### 7.1 Term-definition extraction

The rule-based extraction baseline is evaluated with:

| Metric                        | Description                                               |
| ----------------------------- | --------------------------------------------------------- |
| Term exact match              | Exact string match for the predicted term                 |
| Definition exact match        | Exact string match for the predicted definition           |
| Term + definition exact match | Both term and definition must match exactly               |
| Term token F1                 | Token-level overlap between predicted and gold term       |
| Definition token F1           | Token-level overlap between predicted and gold definition |
| No prediction rate            | Proportion of examples with no predicted extraction       |

### 7.2 Classification tasks

Article-level definition detection and candidate validation are evaluated with:

| Metric           | Description                            |
| ---------------- | -------------------------------------- |
| Macro-F1         | Main metric; average F1 across classes |
| Class F1         | F1 for each class                      |
| Confusion matrix | Error distribution across classes      |

For candidate validation, particular attention is given to false positives of the form:

```text
invalid → accepted
```

These errors are critical because they introduce noisy candidates into the corpus.

## 8. Results

### 8.1 Rule-based term-definition extraction

Test set size: 96 examples.

| Metric                        | Score |
| ----------------------------- | ----: |
| Term exact match              | 0.635 |
| Definition exact match        | 0.865 |
| Term + definition exact match | 0.604 |
| Term token F1                 | 0.902 |
| Definition token F1           | 0.961 |
| No prediction rate            | 0.010 |

The rule-based baseline performs strongly on definition extraction, but exact term boundary detection remains harder.

### 8.2 Article-level definition detection

Test set size: 90 articles.

| Model                             | Macro-F1 | Definition-F1 | TrueNegative-F1 | FP | FN |
| --------------------------------- | -------: | ------------: | --------------: | -: | -: |
| TF-IDF word + Logistic Regression |    0.955 |         0.953 |           0.957 |  0 |  4 |
| TF-IDF word + Linear SVM          |    0.956 |         0.955 |           0.957 |  1 |  3 |
| TF-IDF char + Linear SVM          |    0.989 |         0.989 |           0.989 |  1 |  0 |
| CamemBERT                         |    1.000 |         1.000 |           1.000 |  0 |  0 |

The CamemBERT score reflects performance on this balanced manually verified benchmark and should not be interpreted as proof that article-level definition detection is solved in all uncontrolled settings.

### 8.3 Candidate validation

Test set size: 48 candidates.

| Model                             | Macro-F1 | Accepted-F1 | Invalid-F1 | Confusion matrix    |
| --------------------------------- | -------: | ----------: | ---------: | ------------------- |
| TF-IDF word + Logistic Regression |    0.747 |       0.895 |      0.600 | `[[6, 6], [2, 34]]` |
| TF-IDF word + Linear SVM          |    0.686 |       0.849 |      0.522 | `[[6, 6], [5, 31]]` |
| TF-IDF char + Linear SVM          |    0.625 |       0.875 |      0.375 | `[[3, 9], [1, 35]]` |
| CamemBERT                         |    0.705 |       0.865 |      0.545 | `[[6, 6], [4, 32]]` |

The confusion matrix follows the order:

```text
[[TN_invalid, FP_invalid_to_accepted],
 [FN_accepted_to_invalid, TP_accepted]]
```

Candidate validation is substantially harder than article-level detection. The invalid class remains difficult to detect.

### 8.4 Candidate validation 5-fold cross-validation

The 5-fold cross-validation results were computed for TF-IDF baselines.

| Model                             |      Macro-F1 |   Accepted-F1 |    Invalid-F1 |
| --------------------------------- | ------------: | ------------: | ------------: |
| TF-IDF word + Logistic Regression | 0.705 ± 0.033 | 0.849 ± 0.014 | 0.561 ± 0.054 |
| TF-IDF word + Linear SVM          | 0.710 ± 0.019 | 0.845 ± 0.015 | 0.575 ± 0.030 |
| TF-IDF char + Linear SVM          | 0.678 ± 0.038 | 0.835 ± 0.022 | 0.522 ± 0.056 |

The 5-fold results confirm that candidate validation stabilizes around 0.70–0.72 macro-F1 for classical TF-IDF models.

## 9. Error analysis

For the best candidate validation model on the test set, TF-IDF word + Logistic Regression, 8 errors were observed over 48 examples:

| Error type                             | Count |
| -------------------------------------- | ----: |
| False positives (`invalid → accepted`) |     6 |
| False negatives (`accepted → invalid`) |     2 |

False positive patterns:

| Pattern                  | Count |
| ------------------------ | ----: |
| `terme_colon_definition` |     3 |
| `défini comme`           |     2 |
| `est considéré comme`    |     1 |

False negative patterns:

| Pattern                  | Count |
| ------------------------ | ----: |
| `défini comme`           |     1 |
| `terme_colon_definition` |     1 |

These errors show that invalid candidates may be very close on the surface to valid definitions. Even precise patterns such as colon definitions can introduce false positives when the colon introduces a list, a procedural condition, or an explanatory segment rather than a normative definition.

## 10. Intended use

These baselines are intended for:

* reproducing the experiments reported with NormDef-FR 1.0.0;
* comparing future models against transparent baselines;
* studying the difficulty of normative definition extraction;
* evaluating candidate filtering methods;
* supporting legal NLP research on French legal texts.

## 11. Out-of-scope use

These baselines should not be used for:

* providing legal advice;
* deciding whether a legal provision is currently applicable;
* replacing legal expertise;
* automatically producing authoritative legal definitions;
* making administrative, judicial, or professional decisions.

The outputs of these models must be checked against official legal sources and expert interpretation.

## 12. Limitations

The released baselines have several limitations:

* the rule-based extractor is biased toward explicit definitional patterns;
* rare definition types are underrepresented;
* candidate validation is trained on a moderate-size dataset of 449 examples;
* the candidate validation test set is small, especially for the invalid class;
* CamemBERT may be unstable on candidate validation due to limited supervision;
* no BIO token-classification baseline is included in this release;
* results may not transfer directly to non-codified legal texts, case law, contracts, circulars, or European legal texts;
* article-level detection results are based on a balanced manually verified benchmark and may differ under real-world class imbalance.

## 13. Ethical and legal considerations

The models are trained and evaluated on French legal texts and derived annotations. Their predictions may be incomplete, outdated, or incorrect.

Users must not rely on model outputs as legal advice. Official legal sources and qualified legal professionals should be consulted for legal interpretation or decision-making.
